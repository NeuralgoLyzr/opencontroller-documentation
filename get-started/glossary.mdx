Every term here has one meaning, and the pages use it the same way everywhere. Where the console shows a label, the
label is the term.

| Term | Meaning |
|---|---|
| **Agent** | An asset that acts: calls a model, uses tools, reads data, answers people. The kind OpenController governs. |
| **AI Inventory** | The page listing every asset discovery found, as a list and as a map. |
| **Approval** | A decision on a registration request: register, reject, or later revoke. Needs `registry:decide`. |
| **Asset** | Anything AI-related discovered on a connected platform: an agent or something an agent uses. |
| **Audit log** | The record of who signed in and who changed people, roles, settings and assets. |
| **Awaiting approval** | The state of an asset with a registration request nobody has decided. |
| **Block** | Stop an agent being used on its platform, at once and reversibly. **Disable** on Foundry. |
| **Connection** | One account OpenController reads: an AWS account, a Microsoft tenant, a Google Cloud project, a Databricks workspace, an Anthropic organization or a Snowflake account. |
| **Content rule** | A rule in the LLM gateway that runs a guardrail on prompts or answers. |
| **Control credential** | The optional second credential of a connection, used only for changes. |
| **Control action** | A change OpenController makes on an agent's own platform: share, remove, end organization-wide sharing, publish, block, unblock, delete. |
| **Evals** | The service that judges agents' traces with evaluators and records scores. |
| **Evaluator** | A saved question a judge model answers about each record, producing a score. |
| **Finding** | A failed security policy on one asset, with a severity. |
| **Guardrail** | A named set of checks with settings, tried on text and used by the gateway's content rules. |
| **Guardrail violation** | One trip of a guardrail in the gateway: who, which rule, when. Never the text. |
| **LLM gateway** | The endpoint in front of model providers, with virtual keys, teams, logs and content rules. |
| **Map** | The view from accounts to products to agents to what they use, on AI Inventory and Shadow AI. |
| **Monitor** | A scheduled evaluation that alerts when an agent's scores fall. |
| **Not governed** | An asset of a kind the registration policy does not require to be registered. |
| **Owner** | The person responsible for an agent, named on registration, prefilled from what the platform records. |
| **People** | The page of everyone the platforms name as a creator or owner. |
| **Posture** | The continuous check of the inventory against security policies, producing findings. |
| **Profile** | The bundle of modules an installation runs: `discover`, `govern` or `full`. |
| **Project** | A grouping of traces in observability, with its own key for sending. |
| **Read credential** | The required credential of a connection, used by discovery, Verify and spend. Changes nothing. |
| **Registered** | The state of an asset that has been approved, with an owner, in the registry. |
| **Registration policy** | What **Policies** sets: which kinds must be registered, what a request states, what an approval needs. |
| **Registry** | The list of approved agents, their owners and their states. |
| **Role** | What a person may do: **Viewer**, **Operator**, **Admin** or **Owner**. Each includes the ones before it. |
| **Scan** | One pass of discovery over one connection. |
| **Security policy** | A check under Posture that produces findings, such as "Agents acting with their maker's credentials". |
| **Service account** | An identity for automation, with a role and one or more keys that begin `cpk_`. |
| **Shadow AI** | Assets nobody has registered; also the page that shows them. |
| **Trace** | The record of one run of an agent: its model calls, tools, tokens, cost and errors. |
| **Trace store** | Where traces are kept: ClickHouse, written by the OpenTelemetry Collector. |
| **Virtual key** | A key the gateway issues to an application, scoped to providers, models, budgets and rate limits. |
