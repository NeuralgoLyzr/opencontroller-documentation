OpenController follows one agent through five steps. Each step is a section of the console, and each one builds on
the one before it.

<img className="hidden dark:block" src="/images/diagrams/flow-dark.png" alt="Discover, govern, control, observe and evaluate, in order" />

<Steps>
  <Step title="Discover">
    You connect a cloud or platform with a read credential. OpenController scans it and records every agent and
    everything each agent uses: models, MCP servers, tools, skills, identities, memories, code interpreters,
    credential providers, guardrails, registries and artifacts. The result is the **AI Inventory**, a list and a map,
    and the **Shadow AI** page listing what nobody has registered. Scans repeat on a schedule, so the inventory
    tracks what changes.

    <Card title="Connect a cloud" href="/connect/overview" />
  </Step>
  <Step title="Govern">
    Someone registers an agent, from Shadow AI or from the inventory, naming an owner. The request lands in
    **Approvals**. An approver registers it or rejects it. **Policies** say what an agent must have to be allowed,
    and the **Registry** is the resulting list of approved agents, their owners and their state. Governance is the
    paperwork that makes the next step defensible.

    <Card title="The registry" href="/govern/registry" />
  </Step>
  <Step title="Control">
    For agents that should not run, or should not reach the people they reach, OpenController acts on the platform
    itself. With a control credential it can block or quarantine an agent, unblock it, change who it is shared with,
    end organization-wide sharing, and delete it. What is possible depends on the platform; the control page says
    exactly which combinations work.

    <Card title="Control actions" href="/govern/control-actions" />
  </Step>
  <Step title="Observe">
    Agents that are allowed to run send traces to OpenController's trace store through an OpenTelemetry collector.
    **Observability** shows what each agent did, which models and tools it called, how long it took, what it cost,
    and the issues found in the traces. Traffic through the **LLM Gateway** is logged and checked by **Guardrails**
    on the way in and out.

    <Card title="Observability" href="/monitor/observability" />
  </Step>
  <Step title="Evaluate">
    **Evals** judges the traces: evaluators score an agent's answers for the qualities you choose, on demand or on a
    schedule, so you see whether an agent is getting better or worse after each change.

    <Card title="Evals" href="/monitor/evals" />
  </Step>
</Steps>

## The two credentials

Every connection has a read credential, which discovery needs, and an optional control credential, which the
control step needs. You can run the first two steps with read access only, and grant control per platform when you
are ready to act.

<Card title="Connections and credentials" href="/connect/overview" />

## Where posture fits

Alongside the five steps, **Findings** and **Security policies** check the inventory continuously against the
frameworks you choose and raise findings when an agent falls short.
