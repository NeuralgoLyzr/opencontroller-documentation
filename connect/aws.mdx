OpenController reads an AWS account by assuming a read-only IAM role in it. It keeps no keys for your account: the role's trust policy lets OpenController's own identity in only when it presents the role's external ID. Each scan reads every enabled region.

A connection has two roles, each made from a CloudFormation template OpenController serves and fills in:

| Role | Template | Purpose |
|---|---|---|
| `opencontroller-discover` (read, required) | `/setup/aws/discover-role.yaml` | Discovery, **Verify** and spend. Read-only, and never secret values. |
| `opencontroller-control` (control, optional) | `/setup/aws/control-role.yaml` | Changes who may call the account's AgentCore runtimes and gateways. It never redeploys an agent or reads a secret. |

A third template, `opencontroller-guardrails`, lets the guardrail engine list, read and apply the account's Bedrock guardrails, and nothing else. It is set up from the guardrails area, not from a connection. Keep the default role names, so every account's role ARN has the same shape.

## What is discovered

| In AWS | Becomes |
|---|---|
| Amazon Bedrock AgentCore harnesses and agent runtimes | Agent |
| Classic Bedrock agents, their aliases, and the agents a supervisor delegates to | Agent |
| Their action groups and the Lambda functions that run them | Tool |
| Bedrock knowledge bases: vector store, embedding model, and what they index | Knowledge base |
| The models agents call | Model |
| AgentCore gateways and their targets (MCP, OpenAPI, Smithy, Lambda) | Gateway, MCP server, Tool |
| AgentCore memories, browsers and code interpreters | Memory, Browser, Code interpreter |
| OAuth2 and API key credential providers (names only) | Credential provider |
| Workload identities, and the IAM roles agents run as | Identity |
| Who may call a runtime or gateway (its resource policy), and whether it allows everyone | Identity, and the agent's exposure |
| AgentCore policy engines | Policy engine |
| AWS Agent Registry registries and records (MCP servers, agents, skills) | Registry and its records |
| Bedrock guardrails | Guardrail |
| Container images and code packages agents are deployed from | Artifact |

## Connect

You need the 12-digit account ID and someone who can deploy a CloudFormation stack that creates an IAM role in it. Nothing has to be looked up: the console fills in the principal and a new external ID.

<Steps>
  <Step title="Open the form">
    On **Integrations**, click **Connect**, then **AWS account**.
  </Step>
  <Step title="1. Create the role in the account">
    The form shows **Trusts** (OpenController's principal) and **External ID**, both filled in, and one tab per way to deploy: **Console**, **AWS CLI**, **GitHub Actions**, **GitLab**, **Organization** (a StackSet across an AWS Organization) and **Terraform**.

    In the **Console** tab, click **Download the template**, then in the account open CloudFormation, **Create stack**, **Upload a template file**, name the stack `opencontroller-discover`, paste **Trusts** into `DiscoverPrincipalArn` and the external ID into `ExternalId`, tick the IAM acknowledgement and create it.

    Add `AccessLevel=Scoped` to grant only the calls discovery makes (see below).
  </Step>
  <Step title="2. Connect it">
    Fill in **Name**, **AWS account ID** (the 12-digit account the stack was created in, or the role's ARN if you renamed it) and, optionally, **Regions**. Empty reads every region the account has enabled.

    Under **Control role**, choose **None: discovery only**, **The read role, copied**, or **A role of its own (recommended)**. For a role of its own, the form shows the control role's setup with an external ID of its own; create the `opencontroller-control` stack the same ways, then enter its **Control role ARN**.
  </Step>
  <Step title="Connect and verify">
    Click **Connect**. The connection is verified straight away.
  </Step>
</Steps>

For a whole organization, deploy the StackSet once and connect each account with the same external ID.

<Note>
A control role made by copying the read role cannot change anything, because the read role can only read. Changes are refused until the connection has a control role of its own.
</Note>

## The read role

Its `AccessLevel` parameter sets how wide the reads go. `ReadOnly` (the default) attaches AWS's `ReadOnlyAccess` plus the AgentCore reads it lacks. `Scoped` grants only the calls discovery makes.

**Trust policy.** The principal is OpenController's identity; the external ID is the one the console generated.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<OpenController's principal ARN>" },
      "Action": "sts:AssumeRole",
      "Condition": { "StringEquals": { "sts:ExternalId": "<external ID>" } }
    },
    {
      "Effect": "Allow",
      "Principal": { "AWS": "<OpenController's principal ARN>" },
      "Action": "sts:TagSession"
    }
  ]
}
```

**Scoped permissions.** Control-plane `List` and `Get` calls only, plus the four reads spend uses.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DiscoverAgentCore",
    "Effect": "Allow",
    "Action": [
      "bedrock-agentcore:ListHarnesses", "bedrock-agentcore:GetHarness", "bedrock-agentcore:ListHarnessVersions",
      "bedrock-agentcore:ListAgentRuntimes", "bedrock-agentcore:GetAgentRuntime",
      "bedrock-agentcore:ListGateways", "bedrock-agentcore:GetGateway",
      "bedrock-agentcore:ListGatewayTargets", "bedrock-agentcore:GetGatewayTarget",
      "bedrock-agentcore:ListGatewayRules", "bedrock-agentcore:GetGatewayRule", "bedrock-agentcore:GetResourcePolicy",
      "bedrock-agentcore:ListMemories", "bedrock-agentcore:ListBrowsers", "bedrock-agentcore:ListCodeInterpreters",
      "bedrock-agentcore:ListOauth2CredentialProviders", "bedrock-agentcore:ListApiKeyCredentialProviders",
      "bedrock-agentcore:ListWorkloadIdentities", "bedrock-agentcore:ListPolicyEngines",
      "bedrock-agentcore:ListRegistries", "bedrock-agentcore:GetRegistry",
      "bedrock-agentcore:ListRegistryRecords", "bedrock-agentcore:GetRegistryRecord",
      "agent-registry:ListRegistries", "agent-registry:GetRegistry",
      "agent-registry:ListRegistryRecords", "agent-registry:GetRegistryRecord",
      "bedrock:ListGuardrails",
      "bedrock:ListAgents", "bedrock:GetAgent", "bedrock:ListAgentAliases",
      "bedrock:ListAgentActionGroups", "bedrock:GetAgentActionGroup",
      "bedrock:ListAgentKnowledgeBases", "bedrock:ListAgentCollaborators",
      "bedrock:ListKnowledgeBases", "bedrock:GetKnowledgeBase",
      "bedrock:ListDataSources", "bedrock:GetDataSource",
      "account:ListRegions"
    ],
    "Resource": "*"
  }, {
    "Sid": "Spend",
    "Effect": "Allow",
    "Action": ["ce:GetCostAndUsage", "ce:GetDimensionValues", "cloudwatch:ListMetrics", "cloudwatch:GetMetricData"],

  }]
}
```

At both levels an explicit deny blocks reading secret values, and a deny wins over any allow, `ReadOnlyAccess` included:

```json
{
  "Sid": "NeverReadSecretValues",
  "Effect": "Deny",
  "Action": [
    "secretsmanager:GetSecretValue", "secretsmanager:BatchGetSecretValue",
    "bedrock-agentcore:GetWorkloadAccessToken", "bedrock-agentcore:GetWorkloadAccessTokenForJWT",
    "bedrock-agentcore:GetWorkloadAccessTokenForUserId",
    "bedrock-agentcore:GetResourceOauth2Token", "bedrock-agentcore:GetResourceApiKey",
    "cognito-idp:DescribeUserPoolClient"
  ],
  "Resource": "*"
}
```

## The control role

Its trust policy is the read role's, with its own external ID and `sts:SetSourceIdentity` added, so CloudTrail records the operator behind each change. Its permissions:

```json
[
  {
    "Sid": "ReadBeforeChanging",
    "Effect": "Allow",
    "Action": [
      "bedrock-agentcore:GetAgentRuntime", "bedrock-agentcore:ListAgentRuntimeEndpoints",
      "bedrock-agentcore:GetGateway", "bedrock-agentcore:GetResourcePolicy"
    ],
    "Resource": "*"
  },
  {
    "Sid": "ChangeWhoMayCallAgents",
    "Effect": "Allow",
    "Action": ["bedrock-agentcore:PutResourcePolicy", "bedrock-agentcore:DeleteResourcePolicy"],
    "Resource": [
      "arn:aws:bedrock-agentcore:*:<account>:runtime/*",
      "arn:aws:bedrock-agentcore:*:<account>:gateway/*"
    ]
  },
  {
    "Sid": "NeverRedeployOrReadSecrets",
    "Effect": "Deny",
    "Action": [
      "bedrock-agentcore:UpdateAgentRuntime", "bedrock-agentcore:UpdateAgentRuntimeEndpoint",
      "bedrock-agentcore:UpdateGateway", "bedrock-agentcore:UpdateHarness", "bedrock:UpdateAgent",
      "iam:PassRole", "secretsmanager:GetSecretValue", "secretsmanager:BatchGetSecretValue",
      "bedrock-agentcore:GetWorkloadAccessToken", "bedrock-agentcore:GetWorkloadAccessTokenForJWT",
      "bedrock-agentcore:GetWorkloadAccessTokenForUserId",
      "bedrock-agentcore:GetResourceOauth2Token", "bedrock-agentcore:GetResourceApiKey",
      "cognito-idp:DescribeUserPoolClient"
    ],
    "Resource": "*"
  }
]
```

With control on, OpenController changes who may call an AgentCore runtime or gateway through its resource policy. Statements it writes have Sids starting `Opencontroller`; every other statement is left as it is.

| Action | What it does to the resource policy |
|---|---|
| **Share** | Adds an Allow for an IAM role, user or account, on the runtime and each of its endpoints. |
| **Revoke** | Removes the principal from every Allow and adds a Deny for it. The agent's own account is refused, because denying it would block every caller. |
| **End sharing with everyone** | Removes `*` from every Allow that lets anyone, or anyone in the account or organization, call. Named principals keep their access. |
| **Block** | Adds a Deny of `bedrock-agentcore:Invoke*` from everyone. New calls stop. |
| **Unblock** | Removes that Deny and nothing else. |

A runtime or gateway with a JWT authorizer can only be blocked, since its policy must allow everyone. To control only some agents, add a condition to the role's `ChangeWhoMayCallAgents` statement, such as `aws:ResourceTag/opencontroller-control` equal to `enabled`, and tag the agents to control.

## Verify

| Check | Passes when |
|---|---|
| Assume role | STS returns credentials for the read role with the external ID. |
| Enabled regions | The account has at least one region the scan will read. |
| Control: assume role | With a control role of its own: STS returns credentials for it with its own external ID and the operator as source identity. |

### When OpenController's identity changes

If OpenController's AWS identity changes, for example after a move to another cluster, the connection shows **Trust update needed** and scans of the account fail. Click the badge: the setup now carries the new principal. Deploy the stack again, then click **Verify**.

## Scans

Each account, region and resource family is one source, `aws:<account>:<region>:<family>`. In CloudTrail the calls appear under the role session name `DISCOVERY_AWS_ROLE_SESSION_NAME` (default `opencontroller-discover`). With no AWS connection at all, a scan reads OpenController's own account. `DISCOVERY_AWS_REGIONS` sets the regions a connection with none named reads.

## Remove

Click the trash icon on the row. Scans stop reading the account; what was discovered stays until later scans retire it. The role is not deleted: remove the `opencontroller-discover` and `opencontroller-control` stacks in the account to do that.

## API

- `POST /v1/connections/aws/setup`: the principal, and a new external ID, template address and commands for each role.
- `POST /v1/connections` with `"provider": "aws"` and `aws.read` (`account_id` or `role_arn`, `external_id`), optional `aws.control` and `aws.regions`.
- `GET /v1/connections/{connection_id}/setup`: the connection's own setup, for a trust update.
