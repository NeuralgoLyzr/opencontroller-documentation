OpenController reads a Databricks workspace as a **service principal**, signing in with OAuth machine-to-machine credentials: the principal's application ID and an OAuth secret. One connection is one workspace, on AWS, Azure or Google Cloud. It discovers the workspace's agents, models, MCP servers and skills, and how they connect.

A connection has two service principals:

- **The read principal** (required): discovery, **Verify** and spend sign in as it.
- **The control principal** (optional): Databricks has no control actions. **Verify** only checks that the principal signs in.

## What is discovered

| In Databricks | Becomes |
|---|---|
| Agent serving endpoints | Agent, deployed from its Unity Catalog model |
| Agent Bricks Knowledge Assistants and Supervisor Agents, and the tools each coordinates | Agent |
| Genie spaces | Agent |
| Databricks Apps that use a serving endpoint, Genie space or MCP connection | Agent, running as the app's service principal |
| Registered models: versions, aliases, owner | Model, in its schema and catalog |
| Pay-per-token Foundation Model APIs | Model, with its vendor |
| Custom model and provisioned-throughput endpoints | Endpoint |
| External models behind AI Gateway | Endpoint, using the external model |
| MCP services registered in Unity Catalog, MCP connections, and apps named `mcp-*` | MCP server |
| Unity Catalog skills and Genie Code workspace skills | Skill |
| AI Gateway guardrails, usage tracking, inference tables and rate limits | Guardrail and properties of the endpoint |
| Catalogs and schemas that hold registered models | Registry |

Unity Catalog objects belong to the metastore, so two workspaces on one metastore report each once. Catalogs with no models and apps with no AI resources are left out.

## Before you start

- The workspace URL, such as `https://adb-1234567890123456.7.azuredatabricks.net`. Only Databricks hosts are accepted.
- A workspace admin, to add the service principal and generate its secret.
- The owner of each catalog, or a metastore admin, to grant Unity Catalog privileges.

## Permissions

Each row is one **Verify** check, except skills and MCP services, which are read schema by schema during a scan.

| Surface | Grant |
|---|---|
| Sign in | The service principal added to the workspace, with an OAuth secret |
| Unity Catalog | **USE CATALOG** on each catalog, and **USE SCHEMA** on its schemas |
| Registered models | **EXECUTE** on the models or their schemas, or **BROWSE** for metadata only |
| MCP services | **EXECUTE** on the MCP services |
| Skills | **READ VOLUME** on Unity Catalog skills; **CAN READ** on the `/Workspace/.assistant/skills` folder |
| Model Serving | **CAN VIEW** on each serving endpoint |
| Agent Bricks | **CAN VIEW** on each agent's `ka-…` or `mas-…` endpoint |
| Genie | **CAN READ** on each Genie space |
| Apps | **CAN USE** on each app that hosts an agent or MCP server |

For a whole catalog, from a SQL editor or notebook:

```sql
GRANT USE CATALOG, USE SCHEMA, EXECUTE, READ VOLUME ON CATALOG main TO `<application ID>`;
```

The principal can never query or invoke an endpoint, agent, Genie space or MCP server; read tables, volumes or model files; or read inference tables. The exception is the system billing tables, for spend.

## Connect

<Steps>
  <Step title="Create the service principal">
    In the workspace, open **Settings**, **Identity and access**, **Service principals**, and **Add service principal**. Name it `opencontroller-discover`. Open it, then under **Secrets** choose **Generate secret**. Copy the secret and the principal's **application ID**.
  </Step>
  <Step title="Open the form">
    On **Integrations**, click **Connect**, then **Databricks workspace**.
  </Step>
  <Step title="Fill it in">
    **Name**, **Workspace URL**, **Read service principal: application ID** and **Read service principal: OAuth secret**.

    Under **Control service principal**, choose **None: discovery only**, **The read service principal, copied**, or **A service principal of its own (recommended)** with its application ID and OAuth secret.
  </Step>
  <Step title="Grant and verify">
    Click **Connect**. The next screen lists each grant. When they are in place, click **Verify**.
  </Step>
</Steps>

To rotate the secret, generate a new one in Databricks, then use **Update the secret** on the connection.

## Verify

| Check | Passes when |
|---|---|
| Sign in | The workspace issues the principal a token |
| Unity Catalog | Catalogs are listed |
| Registered models | Models are listed |
| Model Serving | Serving endpoints are listed |
| Agent Bricks | Knowledge Assistants are listed |
| Genie | Genie spaces are listed |
| Apps | Apps are listed |
| Control sign in | With a control principal: the workspace issues it a token |

A check reports **not available on this workspace** when the feature is off, and **refused** with the missing grant when the principal lacks it.

## Scans

Six sources per workspace, named `databricks:<workspace host>:global:<family>`: `unity_catalog.models`, `unity_catalog.skills_mcp`, `serving.endpoints`, `workspace.skills`, `genie.spaces` and `apps`. A scan walks at most 2,000 schemas and reports when it stops short.

Spend reads the account's AI usage from the system billing tables once a day, on a SQL warehouse the principal can use. It needs `USE CATALOG` on `system`, `USE SCHEMA` on `system.billing`, `SELECT` on `system.billing.usage` and `system.billing.list_prices`, and **Can use** on a warehouse. Until then spend reports **needs permission** or **not set up**.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Sign-in refused: `invalid_client` | The application ID or secret is wrong, the secret has expired, or the principal is not in this workspace |
| Cannot reach the workspace | The URL is wrong, or the workspace allows only certain IP addresses. Add OpenController's egress address to the IP access list |
| Models, endpoints, agents or apps missing | Grant the privilege the row above names |
| No catalogs appear | Catalogs holding no registered model are left out by design |

## Remove

Click the trash icon on the row. The stored OAuth secrets are deleted; the service principals stay in the workspace. Delete their secrets, or the principals, to revoke access.
