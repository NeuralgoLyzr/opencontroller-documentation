---
title: "Connect a Microsoft tenant"
description: "Register the Entra apps, grant the Graph, Azure and Power Platform permissions, and see what discovery reads and control changes."
---

OpenController signs in to a Microsoft tenant as **Entra app registrations** with client credentials: a client ID and a client secret each. One connection is one tenant, with two apps:

- **The read app** (required): discovery, **Verify** and spend sign in as it. It needs nothing that changes anything.
- **The control app** (optional): every change OpenController makes in the tenant is made as it, or by an administrator signed in through it. Without one, nothing is changed in the tenant.

One app can do both, but two apps keep the read app read-only. Each surface is granted separately: an Azure role, an Entra directory role, Microsoft Graph permissions, and a Dataverse application user per Power Platform environment. Grant only the surfaces you want; the rest are reported as refused and everything else still works.

## What is discovered

| In Microsoft | Becomes | Needs |
|---|---|---|
| Copilot Studio agents | Agent | Entra role **AI Reader** |
| Microsoft 365 Copilot Agent Builder agents | Agent | Entra role **AI Reader** |
| Agent details: instructions, knowledge, topics, tools, model, owner | Properties, Model, Tool | Dataverse application user |
| Connected agents and the Power Automate flows agents use | Relations, Tool | Dataverse application user |
| Who each Copilot Studio agent is shared with, and co-authors | Relations `can_use`, `can_edit` | Dataverse application user |
| Agent 365 catalog: agents published to Microsoft 365, and Microsoft's own | Agent | **CopilotPackages.Read.All**, an Agent 365 license |
| Entra agent identities | Identity | **AgentIdentity.Read.All** |
| Azure AI Foundry accounts and projects | Registry | Azure **Reader** |
| Foundry agents (prompt, workflow, hosted), their models, tools, connections and content filters | Agent, Model, Tool, Guardrail | Azure **Foundry User** |
| Who may use each Foundry agent | Relation `can_use` | Azure **Reader** |
| Owners, users and groups agents are shared with | Identity | **User.Read.All**, **GroupMember.Read.All** |

## Before you start

- The tenant ID, or a verified domain such as `contoso.onmicrosoft.com`.
- Someone who can register an app and grant admin consent (Application Administrator or Global Administrator).
- For Azure roles: Owner or User Access Administrator on the subscriptions.
- For sharing: a Power Platform administrator for each environment to read.

## Register the apps

<Steps>
  <Step title="Register the read app">
    In **Entra ID**, open **App registrations** and choose **New registration**. Name it `opencontroller`, single tenant, no redirect URI.
  </Step>
  <Step title="Create its secret">
    Under **Certificates & secrets**, choose **New client secret**. Copy the secret's **value**, not its ID.
  </Step>
  <Step title="Grant Graph permissions">
    Under **API permissions**, add the Microsoft Graph **application** permissions from the table below, then **Grant admin consent**.
  </Step>
  <Step title="Assign the roles">
    Assign the Azure roles, the Entra role and the Dataverse application users from the table below.
  </Step>
  <Step title="Register the control app (optional)">
    Register a second app, `opencontroller-control`, the same way, with its own secret, and grant it what the changes you want need.
  </Step>
</Steps>

### The read app's grants

Each row is one **Verify** check.

| Surface | Grant | Where |
|---|---|---|
| Azure subscriptions | Azure role **Reader** on the subscriptions, or a management group above them | Subscription or management group, **Access control (IAM)** |
| Foundry agents | Azure role **Foundry User** (formerly Azure AI User) on the Foundry resources, their subscription or the Tenant Root Group | Same place |
| Copilot Studio inventory | Entra directory role **AI Reader**. Power Platform admin roles do not grant this | **Entra ID**, **Roles and administrators**, **AI Reader** |
| Copilot Studio sharing | The read app as an **application user** in each Power Platform environment, with a role that reads agents, teams and users | Power Platform admin center, the environment, **Users + permissions**, **Application users** |
| Agent 365 catalog | Graph application permission **CopilotPackages.Read.All**, with admin consent, and an Agent 365 license | The app's **API permissions** |
| Agent identities | **AgentIdentity.Read.All**, with admin consent | Same |
| People and groups | **User.Read.All** and **GroupMember.Read.All**, with admin consent | Same |
| Spend: licences | **LicenseAssignment.Read.All**, with admin consent | Same |
| Spend: licence use | **Reports.Read.All**, with admin consent | Same |
| Spend: Azure AI costs | Azure role **Cost Management Reader** on the subscriptions | **Access control (IAM)** |

The **Write access** check lists any Graph permission the read app holds that can change something. The read app needs none of them.

### The control app's grants

| To | Grant |
|---|---|
| Share, revoke, end org-wide sharing, publish and delete Copilot Studio agents | The control app as an **application user** with **System Administrator** in each Power Platform environment |
| Find people and groups to share with | **User.Read.All** and **GroupMember.Read.All**, with admin consent |
| Block Copilot Studio agents | Delegated permission **Power Platform API, CopilotStudio.AdminActions.Invoke**, with admin consent, and the redirect URI below |
| Block Agent Builder and Agent 365 catalog agents, share catalog agents | Delegated permission **Microsoft Graph, CopilotPackages.ReadWrite.All**, with admin consent, the redirect URI, and an Agent 365 license |
| Disable Foundry hosted agents, delete Foundry agents | **Foundry User** on the Foundry resource |
| Share Foundry agents | **Role Based Access Control Administrator** on the Foundry project, conditioned to Foundry Agent Consumer only |
| Route Foundry prompt agents through the LLM gateway | `Microsoft.CognitiveServices/accounts/projects/connections/read`, `write` and `delete`, and **Foundry User** |

Blocking Copilot Studio, Agent Builder and catalog agents is different: Microsoft accepts it only from a signed-in administrator, never from an app. An operator presses **Sign in to Microsoft** on the agent's page and signs in as a Global, AI or Power Platform administrator through the control app. For that, add the redirect URI `<console address>/setup/microsoft/admin-callback` on the **Web** platform under the control app's **Authentication**. The sign-in is kept in memory for about an hour and never stored.

## Connect

<Steps>
  <Step title="Open the form">
    On **Integrations**, click **Connect**, then **Microsoft tenant**.
  </Step>
  <Step title="Fill it in">
    **Name**, **Tenant ID**, **Read app: application (client) ID** and **Read app: client secret** (the value, not the ID).

    Under **Control app**, choose **None: discovery only**, **The read app, copied**, or **An app of its own (recommended)** with its **Control app: application (client) ID** and **Control app: client secret**.
  </Step>
  <Step title="Grant and verify">
    Click **Connect**. The next screen lists each grant. When they are in place, click **Verify**. New grants take a few minutes to reach new tokens, and Azure role assignments up to 10 minutes to reach Foundry.
  </Step>
</Steps>

To rotate a secret, create a new one in Entra, then use **Update the secret** on the connection. The control app can be added, changed or removed later with **Control** on the row.

## What control does, by platform

| Platform | Block | Share |
|---|---|---|
| Copilot Studio | Yes, as a signed-in administrator. Its makers can still open and test it | Share (can use, can edit), remove, end organization-wide sharing, publish |
| Agent Builder | Published agents only, through the Agent 365 catalog | No: only the creator shares, in Microsoft 365 Copilot |
| Agent 365 catalog: published by the organization or a partner | Yes | Share, remove, end organization-wide sharing |
| Agent 365 catalog: Microsoft's own | Yes | No: available to whoever holds the license |
| Foundry hosted agents | Yes: the endpoint is disabled. Sessions in progress are not ended | Foundry Agent Consumer on that agent, and remove |
| Foundry prompt and workflow agents | No: Foundry has no disable for them | The same as hosted |
| Foundry agents published to Microsoft 365 | The copy only; the agent still runs in Foundry | No |

Copilot Studio and Foundry agents can also be deleted from their page, with a cascade for the flows or Bot Services they leave behind. Every change asks for a reason and is written to the audit log.

## Verify

| Check | Passes when |
|---|---|
| Sign in | The read app gets a token. Shows the Graph permissions it carries |
| Azure subscriptions | At least one subscription is visible |
| Copilot Studio inventory | The inventory answers; shows how many agents |
| Copilot Studio sharing | At least one environment lets the read app in |
| Agent 365 catalog | The catalog answers |
| Agent identities | Graph lists agent identities |
| Write access | Informational |
| Control sign in | The control app gets a token |
| Control: Copilot Studio sharing | At least one environment lets the control app change sharing |

## Scans

Sources are named `microsoft:<tenant>:global:<family>`. Each Foundry project and each environment's sharing is its own source, so one refused project does not hide the rest.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `AADSTS7000215: Invalid client secret` | The secret's ID was entered instead of its value. Create a new secret and update the connection |
| `AADSTS7000222: client secret expired` | Create a new secret and update the connection |
| Copilot Studio inventory refused | Assign the Entra role **AI Reader** |
| Every action: "has no control app" | Set a control app with **Control** on the row |
| Block: `AADSTS50011: redirect URI does not match` | Add the redirect URI above to the control app |
| Foundry agents: `does not have …/agents/read` | Assign **Foundry User** |

## Remove

Click the trash icon on the row. The stored secrets are deleted; the app registrations, their role assignments and application users stay in the tenant. Delete the app registrations in Entra to revoke everything.
