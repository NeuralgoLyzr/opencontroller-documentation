OpenController reads a **Claude Platform organization** (the Claude API, managed in the Claude Console) with an **Admin API key**. One connection is one organization. It discovers the Claude models the organization's applications called over the last 30 days, and the API keys they call them with, each with its workspace and the tokens it used. For spend it reads the organization's cost report and the Claude Code analytics report.

The key is used only to read. OpenController never creates, changes or revokes anything with it, and never calls a model. This connection has no control credential.

## What is discovered

| In the Claude Platform | Becomes |
|---|---|
| Each model called over the last 30 days | Model, with its input, output and cache tokens, the workspaces it was called from, and how many keys called it |
| Each active API key: name, workspace, creator, status, expiry, partial hint | Identity (type `api_key`), with its tokens over the last 30 days |
| Which API key called which model | The key uses the model |
| A key no longer active that called a model in the window | Identity, referenced by the model |
| Workspaces | The `workspace` property of each key and model |

Members are read only to name who created each key. Usage outside every workspace is shown as **Default workspace**.

## Before you start

- A Claude Platform organization. Individual accounts have no Admin API.
- An **organization admin**: only admins can create Admin API keys.
- The organization's ID, from the Claude Console under **Settings**, **Organization**. It is a GUID.

Claude Enterprise seats report through a separate Analytics API key, which this connection does not read.

## Connect

<Steps>
  <Step title="Create the Admin API key">
    In the Claude Console, as an organization admin, open **Settings**, **Admin keys**, and **Create admin key**. Name it `opencontroller`. Copy the key (`sk-ant-admin…`); the Console shows it once.
  </Step>
  <Step title="Copy the organization ID">
    Under **Settings**, **Organization**, copy the organization ID.
  </Step>
  <Step title="Open the form">
    On **Integrations**, click **Connect**, then **Anthropic organization**.
  </Step>
  <Step title="Fill it in">
    **Name**, **Organization ID** and **Admin API key**. A workspace API key (`sk-ant-api…`) is refused.
  </Step>
  <Step title="Verify">
    Click **Connect**, then **Verify**. The **Setup** dialog lists what the key reads: sign in, workspaces and API keys, usage and cost.
  </Step>
</Steps>

To rotate the key, create a new one in the Console, use **Update the key** on the connection, then delete the old one in the Console.

## Permissions

An Admin API key reads everything below; there is no narrower Admin API key. Each row is one **Verify** check.

| Check | Passes when |
|---|---|
| Sign in | The key is accepted and belongs to the organization the connection names |
| Members | Members are listed |
| Workspaces | Workspaces are listed |
| API keys | Active API keys are listed |
| Usage and cost | Yesterday's usage and cost reports can be read |
| Claude Code analytics | Yesterday's Claude Code report can be read |

A key of another organization fails sign-in, so a connection never reports another organization's estate. The key can never see an API key's secret value: the API returns only a partial hint.

## Scans

Two sources per organization, named `anthropic:<organization id>:global:<family>`: `api_keys` and `models`. Each scan reads the last 30 days of usage, by day, model, workspace and API key. A model nobody has called for 30 days is retired.

Spend reads the last 35 days from two sources: `anthropic.cost`, the organization's cost report by workspace and line item (billed), and `anthropic.claude_code`, each person's or key's Claude Code tokens and estimated cost by model (attributed, never added to a total).

## Troubleshooting

| Symptom | Fix |
|---|---|
| `anthropic.admin_key must be an Admin API key` | The key is a workspace key. Create one under **Settings**, **Admin keys** |
| Sign-in refused (HTTP 401) | The key is wrong or revoked. Create a new one and rotate it |
| Sign-in refused (HTTP 403) | The key is not an Admin API key |
| The Admin API key belongs to organization … | The key was created in another organization |
| No models | No API calls in the last 30 days |
| A check fails with HTTP 429 | The Admin API's rate limit. Try again later |

## Security and data handling

The key is kept in your secrets manager, never returned by the API, never logged, and sent only to `https://api.anthropic.com`. Stored: model names and token totals; each key's name, workspace, status, expiry, creator and partial hint; members' emails only as a key's creator. Never read: prompts, responses, files or conversations.

## Remove

Click the trash icon on the row. The stored key is deleted. The Admin API key still works in the Claude Platform until you delete it under **Settings**, **Admin keys**.
