Evals is OpenController's judging service. It reads records from a trace store, a span, a whole run or a conversation at a time, and has a model answer a question about each one: did the answer address the request, did it leak data, was it polite. The answers become scores, which show on the **Scores** page, feed the policy **OBS-2 Traced agents nobody evaluates** on [Findings](/posture/findings), and let monitors say when an agent got worse. The pages live under **Evals** in the console.

## Connecting the service

The evals service is its own container with its own MongoDB database. Until it is connected, the Evals pages say **No evals service connected** and link to the settings.

<Diagram name="evals" alt="The evals service reads records, asks a judge model, and writes scores that pages and monitors read" />

<Steps>
<Step title="Deploy it">
With the Helm chart, `evals.enabled` installs it; `evals.existingSecret` names the Secret that holds its keys (by default `oc-<org id>-evals-env`, as [Install](/setup/install) names it), `evals.database` the MongoDB database (default `evals`) and `evals.workers` how many judging workers run. Run on its own, it reads `PORT` (default `8080`), `MONGODB_URI`, `MONGODB_DATABASE`, `EVALS_API_KEY` (what the platform signs in with), `EVALS_SECRET_KEY` (what it seals connection secrets with), `EVALS_WORKERS` (default 2), `EVALS_MODEL_CALLS` (default 4 at a time), `EVALS_MODEL_CALLS_PER_MINUTE` (default 60), and `EVALS_CODE_EVALUATORS=true` to allow code evaluators. `EVALS_WEBHOOK_HTTP` and `EVALS_WEBHOOK_PRIVATE` let monitor alerts reach plain-HTTP or private-network webhooks.
</Step>
<Step title="Open Settings, then Evals">
Set **Provider** to **opencontroller evals**. Enter the **Base URL**, for example `https://evals.example.com`, or `http://evals:8080` beside a local stack. Choose **Token** as the sign-in and paste the service's API key, or **No sign-in** when the network does the authentication. The token is kept in the secrets manager and cannot be read back.
</Step>
<Step title="Save and check">
Click **Save**, then **Check connection**. The console probes the service's health and reads the evaluator kinds it offers.
</Step>
</Steps>

The platform calls the service on your behalf, so your browser never needs to reach it.

## The overview

The **Evals** front page opens with **Get started**: connect a model, make a dataset, write an evaluator, check it agrees with you, test a prompt version, connect a trace store, set a monitor. Each step links to its page and is ticked off once done.

Below it, for a window of **Last 24 hours**, **Last 7 days** or **Last 30 days**:

| Panel | What it shows |
|---|---|
| **Resources** | Counts of Evaluators, Templates, Tasks, Running, Monitors, Datasets, Results, Errors, Trace stores and Models |
| Metrics | **Results** judged, **Quality** (the share judged well, each evaluator by its direction), **Error rate** (records that could not be judged) and **Judge tokens** spent |
| **Quality by evaluator** | Each evaluator's mean score, worst first; the bar is the share that went well |
| **Latest verdicts** | The newest results, each opening its record |

## The pages

<CardGroup cols={2}>
<Card title="Evaluators and tasks" href="/monitor/evaluators-and-tasks">
Write a judge, run it over a project once or continuously, and read every score it gave.
</Card>
<Card title="Monitors and datasets" href="/monitor/monitors-and-datasets">
Judge on a schedule and alert on change, test against a dataset with known answers, keep prompts in versions, and connect stores and models.
</Card>

| Page | What it holds |
|---|---|
| **Evaluators** | Saved judges: a prompt, and the labels or questions a model answers about each span, trace or session |
| **Tasks** | Evaluators run over a trace store: once over a window, or continuously as traffic arrives |
| **Scores** | Every judgment your tasks and monitors made, newest first |
| **Monitors** | Evaluators run on a schedule over the traffic since the last run, reporting what got worse, crossed a line or could not be judged |
| **Datasets** | Test sets of examples, with the grades you would give them, and the experiments that answer and grade every row |
| **Prompts** | The prompt hub: versioned prompts you can try on a dataset |
| **Connections** | The trace stores evals reads records from, and the models it judges with |
