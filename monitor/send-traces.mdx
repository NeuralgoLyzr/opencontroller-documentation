title: "Send traces"
description: "Point an agent's OpenTelemetry exporter at OpenController with a service-account key and a project, with the install line and start-up code for every framework the console supports."
icon: "send"

An agent sends its traces to OpenController's intake, an OTLP endpoint on the console's own address. The intake checks the key, stamps the project and its agent onto the trace, and forwards it to the collector that writes the trace store. No OpenController library is involved: the agent runs an OpenTelemetry SDK with an instrumentor for its framework, and three environment variables tell the SDK where to send.

Each project's **Setup** page writes everything on this page filled in with your project's id and your console's address. Open a project, then **Setup**, and choose the framework the agent is built on.

## Two conventions

Instrumentors write a span's attributes in one of two vocabularies. OpenController reads both, adds the other to every AI span, and shows them the same on every page. The choice is only about which instrumentor fits the agent.

| Convention | Instrumentors | Prompts and answers |
|---|---|---|
| **OpenInference** | Arize's, the most frameworks, in Python and TypeScript. | Recorded on every span by default. |
| **OpenTelemetry GenAI** | OpenTelemetry's own, writing its GenAI semantic conventions. Fewer frameworks, still in beta. | Off until the environment turns them on: `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` and `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=SPAN_ONLY`. Without them, a step arrives with its model, tokens and timing but not what was said. |

The two can be mixed, even in one run. Spans that are not AI, such as HTTP requests, database queries and the app's own functions, can go along with them. They are kept as they came, and show in the run's steps beside the model calls, without a model or cost.

## What every agent needs

### The environment

Every OpenTelemetry SDK reads these three variables. Set them where the agent runs:

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=https://opencontroller.example.com/otlp
OTEL_EXPORTER_OTLP_HEADERS=x-api-key=<your key>,x-project=<project id>
OTEL_SERVICE_NAME=<project slug>
```

- `OTEL_EXPORTER_OTLP_ENDPOINT` is the console's origin followed by `/otlp`. The SDK appends `/v1/traces`.
- `OTEL_EXPORTER_OTLP_HEADERS` carries the key as `x-api-key` and the project as `x-project`. The project's id is on its **Settings** page under **Sending traces**; its name works too. The project decides which agent the traces belong to, whatever the code says.
- `OTEL_SERVICE_NAME` names the sender. The **Setup** page writes a lowercase slug of the project's name, with every run of other characters replaced by a dash: a project named `Support Agent` becomes `support-agent`.

With OpenTelemetry GenAI, the **Setup** page adds the two variables from the table above, so the instrumentors write the conventions' latest names and keep prompts and answers on the spans.

### The key

Traces are sent with an OpenController API key, a [service account's](/setup/service-accounts), the same kind the API takes. Its role must allow `observability:send`: the operator or administrator role, or a custom role that holds only that permission, for a key that can do nothing but send traces.

On the **Setup** page, choose a service account and click **Create key**. The key is shown once: copy it into `OTEL_EXPORTER_OTLP_HEADERS`. A viewer's key cannot be used; pick another account, or give it the operator role.

### The protocol

<Warning>
The intake takes OTLP over HTTP only, as protobuf or JSON, gzipped or not. It does not take gRPC. Where an SDK or helper package offers both, pick the HTTP exporter: `opentelemetry-exporter-otlp-proto-http` in Python, `@opentelemetry/exporter-trace-otlp-proto` in Node.
</Warning>

## Frameworks

The install line and the start-up code below are what the **Setup** page writes for each framework. Run the code once at start-up, before the agent runs; in Node, before anything imports the framework. The exporter reads where to send, the key and the project from the environment above.

### Without code

Claude Code needs no code. On the **Setup** page, choose **Claude Teams / Enterprise**, and the page writes a settings file for the organization's managed settings. The file turns Claude Code's telemetry on and sends its traces to the intake over `http/protobuf`, with the key and project in the headers. It turns the metrics and logs exporters off, and has Claude Code record user prompts and tool details and content. See [Claude Code](/connect/claude-code).

from opentelemetry import trace

### Your own spans

Any OpenTelemetry SDK, in any language, sends with the environment above. Write a span for each step, and give a model call its attributes in one convention. Its model, tokens and messages are what the pages read for cost and the conversation. Choose **Your own spans** on the **Setup** page for this code with your project filled in.

The attributes a model call's span carries, in each convention:

| What | OpenInference | OpenTelemetry GenAI |
|---|---|---|
| The kind of step | `openinference.span.kind` set to `LLM` | `gen_ai.operation.name` set to `chat` |
| The provider | `llm.provider` | `gen_ai.provider.name` |
| The model | `llm.model_name` | `gen_ai.request.model` and `gen_ai.response.model` |
| Tokens | `llm.token_count.prompt` and `llm.token_count.completion` | `gen_ai.usage.input_tokens` and `gen_ai.usage.output_tokens` |
| The conversation | `input.value` and `output.value`, and the numbered `llm.input_messages.<n>.message.role` and `.content`, likewise `llm.output_messages` | `gen_ai.input.messages` and `gen_ai.output.messages`, each a JSON list of messages with `role` and `parts` |

## Listen for the first trace

The last step of the **Setup** page waits for the project's first trace from the moment you open it. It keeps listening while you start the agent in a terminal behind it. When traces arrive, the page says so with the count, and **View traces** opens the project's **Traces** for the last hour.

To try the way there without any code, click **Send a test trace**. It sends one span from the console as you, so your own role must allow `observability:send`; otherwise the button says an operator can.

## What OpenController reads from a span

OpenController reads the OpenTelemetry GenAI semantic conventions first and OpenInference second, so either instrumentation works without mapping. In words:

| It reads | From |
|---|---|
| The model | The response model, else the requested model, else the OpenInference model name |
| The provider | The GenAI provider name or system, the OpenInference provider or system, or the gateway's provider name |
| Input and output tokens | The GenAI usage counts (new and old names), else the OpenInference token counts |
| Cached input tokens | The GenAI cache-read count, else the OpenInference prompt cache detail |
| Cost | The GenAI usage cost, else the OpenInference total cost |
| The kind of step | The OpenInference span kind, else the GenAI operation name: chat and text completion are model calls, embeddings an embedding, execute tool a tool, invoke or create agent an agent |
| The session | The GenAI conversation id, else `session.id` |
| The user | `enduser.id`, `user.id` or the GenAI request user |
| The customer, gateway key and team | The LLM gateway's customer, virtual key and team attributes, or a customer name attribute |
| The tool | The GenAI tool name, else `tool.name` |
| What was asked and answered | The input and output values or messages, the prompt and completion, the first message's content, a tool call's arguments and result, or a retrieval query |

Two things are not read from the sender. The agent a trace belongs to is the project's agent, written by the intake as the resource attribute `agent.id`, so a sender cannot claim another agent. The project is the resource attribute `opencontroller.project`, set the same way.

<Note>
A model call is counted once per trace, at the deepest span that carries usage. When a call goes through the LLM gateway, the gateway's span carries the price.
</Note>
