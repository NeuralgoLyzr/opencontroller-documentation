<Note>Needs the **Observability** module and a connected trace store. See [Modules](/administer/modules).</Note>

An issue is one step failing with one error. **Failures** counts the failed spans and **Runs** the runs it broke. The list refreshes every 30 seconds.

## How failures are grouped

- **Numbers in messages are masked** as `#`. The same error with a different order id or retry time is one issue, not many.
- **Only the deepest failure counts.** A parent step that failed because a child step failed is not listed again.

## Open the failures

Select a row to open the project's **Spans** filtered with `name = '<step>' and status = 'error'`. Edit the query to narrow it. **Latest run** opens that run in **Traces**, with every step around the failure. What was asked and answered shows only to Operators and above.

Issues is a page of each project. For failures across every project, use **Top issues** on the Observability **Overview**.

Issues alerts no one. To be alerted when failures grow, make an evals monitor with the **Errors** detector.

## Who can use it

- **Viewer** reads the issues and opens the failing spans and runs, without what was asked and answered. A member of the project's team reads them too.
- **Operator**, **Admin** and **Owner** also read what was asked and answered.
