A security policy is a detector the posture runs over the AI inventory. When it is on, it runs at each evaluation and lists what it finds on [Findings](/posture/findings). When it is off, it does not run.

## The Security policies page

Go to **Posture** > **Security policies**.

| Control | What it does | Least role |
|---|---|---|
| **By category** / **By framework** | Reads the tree on the left by category and class, or by framework and control. Each branch shows how many policies it holds. | Viewer |
| **Find a policy** | Finds policies by title or by why they matter. | Viewer |
| **Every provider** / a cloud | Shows only the policies that cover that cloud. **Clear the filters** removes the cloud and the search. | Viewer |
| **On** switch | Turns one policy on or off. The change is saved at once, and findings follow within a minute. | Admin |
| **Turn all on** / **Turn all off** | Turns every policy in the chosen branch on or off. With a cloud chosen, the buttons say **everywhere**: a policy turns on or off on every cloud it covers. | Admin |
| **About** a framework | In a framework branch, opens that framework's guide. | Viewer |
| **Framework guides** | Opens the guides: what each framework is, its official documentation, and how the policies cover it. | Viewer |

Select a policy's name to open its panel: **Detector** (the on/off switch), **Clouds it covers** and **Frameworks it answers to**. A policy that is on but cannot run says **Not running** and why.

### Allowed model providers

The policy **SUP-3**, *Models from providers the organization does not allow*, runs only once you set the providers your organization allows. Open **SUP-3** and, under **Allowed model providers**, select each provider to allow, or type one in **Another provider** and select **Allow**. A model from any other provider is then a finding. With none allowed, this policy does not run. Changing the list needs the **Admin** role.

## Policies by framework

Each row is a category of policies, as Findings groups them, and each number counts the controls in one framework that the category's policies answer. Pick a framework to see its controls. What each framework is, and every control it maps to, is on [Frameworks](/posture/frameworks).

## Categories

| Category | What goes wrong |
|---|---|
| **Exposure** | Assets others can reach or use without signing in. |
| **Identity and access** | Agents and keys acting with more access than they should, or with credentials that never end. |
| **Data and secrets** | Credentials stored where they leak, and agents that can move private data out. |
| **Agency** | Agents that can do harm: destructive tools, code they write, other agents. |
| **Supply chain** | Components that are not approved or not encrypted. |
| **Runtime protection** | Agents whose calls skip the LLM gateway and guardrails. |
| **Governance** | Assets nobody registered, owns or uses. |
| **Observability** | Agents nobody traces or evaluates. |

## Who can use it

| Role | What they can do |
|---|---|
| **Viewer** | Read every policy, its frameworks and the framework guides. |
| **Operator** | Also **Evaluate now** on [Findings](/posture/findings). |
| **Admin** | Also turn policies on and off, and set the allowed model providers. Every change is recorded in the audit log. |
| **Owner** | Everything an Admin can do. |
