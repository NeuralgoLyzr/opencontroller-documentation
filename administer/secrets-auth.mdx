## Secrets

OpenController keeps every secret in your organization's secrets manager. Values are **write-only**: you set or rotate them here, but nobody can read them back. Only the server reads them. They are never shown, logged or returned by the API.

### Where secrets are kept

**Kept in** names the store, chosen when OpenController is deployed (`SECRETS_PROVIDER`): **HashiCorp Vault** (KV version 2), **AWS Secrets Manager**, **Azure Key Vault** or **Google Secret Manager**. **MongoDB, sealed with DISCOVERY_SECRET_KEY** seals them in OpenController's database, for development and single-node installs only. With **No secrets manager**, nothing can be stored and integrations that need a client secret cannot be added; whoever runs OpenController must set a store and restart.

### What you change here

Only **Platform** secrets (keys OpenController itself uses, for example `platform/anthropic-api-key`, the assistant's key) and **Custom** secrets (`custom/<name>`) are changed here. Integration client secrets are changed on the integration, the SAML signing key by reconnecting single sign-on, and module credentials in [Modules](/administer/modules).

- **New secret**: the **Name** takes letters, digits, `-` and `_`, and `/` to nest, for example `evals/openai-api-key`.
- **Rotate value** stores a new version (`v2`, `v3`, …). Whatever uses the secret reads the new value. The old value is not kept anywhere you can read it.
- **Delete** removes every version from the secrets manager. Whatever uses it stops working until it is set again. This cannot be undone.

### Activity

**Activity**, under the list, shows every change to a secret and who made it. Values are never recorded. It shows the latest 50 changes.

## Authentication

**Authentication** shows how people and machines prove who they are. It is read only. You connect single sign-on under [Single sign-on](/administer/sso); the rest is set in the server's configuration.

**Static API keys** are kept in the secret `platform/api-keys`. Prefer `cpk_…` keys from [Service accounts](/administer/service-accounts).

Sessions default to an **Idle timeout** of 12 hours and a **Longest session** of 168 hours (7 days). **Console address** is where browsers reach the console, and single sign-on's addresses (redirect URI, SAML Reply URL) start with it. It shows "not set" when the deployment has not set `DISCOVERY_PUBLIC_URL`.

## Who can use it

- **Secrets** and **Authentication** need the **Admin** role, to read them as well as to change secrets.
- Only an **Owner** can change the secrets that decide who signs in: `platform/api-keys`, `platform/handoff-key` and `platform/scim-token` (the `secrets:sign-in` permission).
