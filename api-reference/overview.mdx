The console runs on the OpenController API, and anything the console can do, a script can. This page is what every
call has in common. The endpoint pages beside it are generated from the API's OpenAPI document.

## Base path

Every route is under `/v1` on your OpenController host:

```
https://<your-opencontroller-host>/v1
```

Requests and responses are JSON. Four routes sit outside `/v1` and need no sign-in: `/healthz`, `/readyz`,
`/version` and the error catalog at `/v1/problems`.

## Authentication

Machines sign in with a **service account**, which has a role and any number of keys. A key looks like
`cpk_<key id>_<secret>`, is minted once, shown once, and kept only as a SHA-256 hash.

Send it as a bearer credential:

```
Authorization: Bearer cpk_<key id>_<secret>
```

The same key is also accepted in an `X-API-Key` header. When both headers are present, `Authorization` is read.
Keys are checked before any identity provider, so a script's call never waits on single sign-on. A request with no
usable credential gets `401` with `WWW-Authenticate: Bearer realm="opencontroller"`.

### Create a key

**Who can do this.** `service-accounts:write` (the admin role). You can give a service account only a role whose
every permission you hold yourself.

<Steps>
  <Step title="Create the service account">
    Open **Settings → Service accounts** and click **New service account**. Give it a name, a role (viewer, operator, admin, or
    one of your organization's own roles) and, if you like, a description. A service account can never be owner.
  </Step>
  <Step title="Mint a key">
    Click the account's keys button in the table (it reads **0 keys** at first), or **Manage keys** in its row menu, then click **Mint key**. The secret appears in a dialog titled **Shown exactly once**.
    Store it now, then click **I stored it**. It cannot be recovered; to replace it, mint a new key and revoke this
    one.
  </Step>
  <Step title="Revoke or disable when needed">
    **Revoke** stops one key at once. Disabling the service account stops every key it has. The keys table shows
    each key's hint, when it was created and by whom, and when it was last used.
  </Step>
</Steps>

<Note>
An installation can also hold static API keys in the secret `platform/api-keys` (`name:role=key`, comma-separated,
each key at least 32 characters, never the owner role). Changing that secret needs `secrets:sign-in`, which only
the owner holds by default. Service accounts are the way to go for anything new.
</Note>

## Roles and permissions

A caller holds one role. Each built-in role includes the ones below it.

| Role | May |
|---|---|
| `viewer` | Read the inventory, map, findings, scans and audit log, and ask the assistant. |
| `operator` | Also run scans and verifications, request registrations, try text on guardrails, and change agent sharing. |
| `admin` | Also add, change and remove integrations and their credentials, decide registrations, and manage people, teams, secrets and service accounts. |
| `owner` | Also the organization itself: single sign-on, who gets which role, and the organization's own roles. |

Every route needs one permission, written `resource:action`. A role holds a set of them. `GET /v1/access/policy`
lists what each route needs, `GET /v1/access/permissions` describes every permission, and `GET /v1/me` says which
ones you hold. The permissions, with the least built-in role that holds each:

Some installations run fewer modules; a route of a module that is off answers `404` with the code
`feature_disabled`. A caller without the permission gets `403` with a detail such as
`this needs scans:run (the operator role); you have viewer`.

## Errors

Every failing route answers an RFC 9457 problem document, with `Content-Type: application/problem+json`:

```json
{
  "type": "/v1/problems/not_found",
  "title": "Not found",
  "status": 404,
  "detail": "asset not found",
  "instance": "/v1/assets/ast_3f1c9a2b7d4e8f60",
  "code": "not_found",
  "request_id": "d2b228cd13bd01be"
}
```

<ResponseField name="code" type="string">
  The value to branch on. Each code always carries the same HTTP status.
</ResponseField>
<ResponseField name="detail" type="string">
  What went wrong, in words a client may show. For an internal error it is only "an unexpected error occurred".
</ResponseField>
<ResponseField name="request_id" type="string">
  Quote it to support; it matches the server's log line.
</ResponseField>
<ResponseField name="errors" type="array">
  For `invalid_request` only: each field at fault, as `field`, `code` (`required`, `max`, `min`, `oneof`, `url`,
  `invalid`) and `message`.
</ResponseField>

| Code | Status | Retry? | Meaning |
|---|---|---|---|
| `invalid_request` | 400 | no | A field is missing, out of range or not allowed; `errors` lists each. |
| `invalid_json` | 400 | no | The body is not the JSON the route takes. |
| `unauthenticated` | 401 | no | No usable credential. |
| `forbidden` | 403 | no | The caller's role does not hold the permission the detail names. |
| `not_found` | 404 | no | Nothing there, or nothing the caller may see. |
| `feature_disabled` | 404 | no | The route exists, but this installation does not run that part of the product. |
| `method_not_allowed` | 405 | no | The route does not take this method. |
| `conflict` | 409 | no | The request clashes with the current state: a name taken, or a step not allowed from this state. |
| `request_too_large` | 413 | no | The body is larger than the route accepts. |
| `rate_limited` | 429 | yes | Too many requests; wait as long as `Retry-After` says. |
| `internal_error` | 500 | yes | Something failed on the server; quote `request_id`. |
| `not_implemented` | 501 | no | The route cannot do this yet. |
| `upstream_unavailable` | 502 | yes | A service the request depends on failed or refused OpenController's credentials. |
| `not_ready` | 503 | yes | A dependency is not available yet. |
| `timeout` | 504 | yes | The request took longer than allowed and was stopped. |
| `upstream_timeout` | 504 | yes | A service the request depends on did not answer in time. |

`GET /v1/problems` returns this catalog, and `GET /v1/problems/{code}` one entry.

## Pagination

Lists that page take `limit` and `offset` as query parameters and answer with the items under a named key plus
`total`, `limit` and `offset`:

```json
{ "assets": [ … ], "total": 42, "limit": 50, "offset": 0 }
```

| Route | Default `limit` | Maximum |
|---|---|---|
| `GET /v1/assets` | 50 | 500 |
| `GET /v1/scans` | 20 | 200 |
| `GET /v1/registry/registrations` | 50 | 500 |

Each endpoint page says whether it pages. Some lists, such as `GET /v1/connections`, return everything.

## Health

| Route | Answers |
|---|---|
| `GET /healthz` | `{"status":"ok","version":"…"}` as long as the process is up; touches no dependency. |
| `GET /readyz` | `{"status":"ready","version":"…"}` when every dependency answers a ping; otherwise `503` with the code `not_ready`. |
| `GET /version` | The build: version, commit, build date, Go version and whether the tree was dirty. |

Point your liveness and readiness probes at the first two.
