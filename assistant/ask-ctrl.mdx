Ctrl is the assistant built into the console. You ask in plain language, and it looks things up in your inventory,
scans, connections, findings, traces and the rest of the API. It answers with links to the pages and assets it
names, and can open a console page to show you the answer. When a change would help, it proposes one, and the change
runs only when you click **Confirm**.

## Where to find it

- **Ask Ctrl** in the sidebar opens the assistant as a panel on the right of every page.
- **Ask** in the toolbar of the inventory map opens the same panel.
- **Ask Ctrl** on Observability pages opens it too, and ⌘J toggles it anywhere.

The panel's header reads **Ctrl** with the model it answers with. Until you ask, it says:

> Ask about your agents, clouds, scans or connections. I look things up live, can open the page that shows the
> answer, and ask before I run anything.

On Observability pages it says instead that it reads the traces live and can open the run that shows the answer.
Below it are suggested questions that change with the page you are on. **New conversation** clears the
conversation. On the Evals pages the same panel is a different assistant, for evaluators and datasets, which this
page does not cover.

## What it can answer

An answer is built from lookups, each shown as a step above the answer, such as `▸ search "bedrock" → 4 matches`.
One answer may make up to 40 lookups, over at most 12 round trips to the model. The model's thinking streams to the
panel as it works, as **Thinking…**, and folds to **Thought for** and the time it took once it is done.

Ask Ctrl has two kinds of lookup. The first is its own, built for the questions people ask most:

| Lookup | What it reads | Needs |
|---|---|---|
| Estate summary | Counts of live assets by kind, provider and account | `assets:read` |
| Search assets, get asset, assets with a property | Assets by name, filter or property, and one asset in full with what it uses and is used by | `assets:read` |
| Recent scans, get scan | The latest discovery scans, each source and why it failed | `scans:read` |
| Connections | The connected accounts and tenants, and their last verification | `connections:read` |
| Findings | The open posture findings on the assets you may see | `posture:read` |
| Trace projects, find traces, get trace, get session, trace issues, trace usage | Your agents' runs: projects, failures, latency, tokens and cost, and a run step by step | `observability:read` |

The second is one tool per read operation of the API, made from the API's own description. Through them Ask Ctrl
can read anything the console can show: the registry, approvals, the audit log, the LLM gateway's keys and logs,
guardrails, spend, and so on.

A tool is offered only when two roles both hold its permission: yours, and Ask Ctrl's own. A role that may not read
connections, say, does not see them through the assistant either, whatever Ask Ctrl's role allows. Ask Ctrl's role
is Viewer until an administrator sets it with `PUT /v1/access/agent`; see
[Ask Ctrl's role](/administration/roles#ask-ctrls-role). Every lookup runs through the API as you, so it is
authorized, bounded and logged as any request.

What agents were asked and answered appears in trace lookups only when you hold `observability:content`. Without
it, the assistant is told the content is hidden and says so rather than guessing.

Scans and findings are part of the assistant only in an installation that runs discovery and posture; traces only
in one that runs observability.

Credentials never pass through the model. Operations about them, such as secret values, minted keys and tokens,
passwords and interactive sign-ins, are not offered, and credential fields are stripped from every other
operation.

## Steering the console

Ask Ctrl can also act on what is on your screen. The console offers it the commands of the page you are on. One is
always there: **Open a page of the console**. An Observability project adds **Show this project's traces, spans or
sessions over a window, filtered** and **Turn the live updates of this view on or off**. These commands change only
what you see: a view, a filter, a selection. When Ask Ctrl uses one, the console runs it and tells Ask Ctrl what changed.

## Proposed changes

Ask Ctrl never makes a change. When an answer calls for one, such as running a scan, verifying a connection or
approving a registration, the operation becomes a proposal. A card appears under the answer with what the change
is, in words, and the API call it would make, with **Confirm** and **Dismiss**.

- A proposal waits 15 minutes. After that it expires, and Ask Ctrl has to propose it again.
- Only the person it was proposed to can confirm it, and only once.
- **Confirm** makes the call as you, with your permissions as they are at that moment. The audit log records the
  change as you, via Ask Ctrl.
- **Dismiss** lets it go. Nothing is made.

Either way, Ask Ctrl is told what you did and how the API answered, and goes on from there. It is told never to say
a proposal ran before you confirmed it, and the API refuses any unconfirmed change from it, whatever its role.

## How it runs

Ask Ctrl's runtime is a service of its own, deployed beside the API. It runs the assistant's agent on Codex, through
Codex's app-server, with every built-in tool turned off, and holds no credentials, no data and no conversations.
For each answer the API opens a turn with a token good for that answer alone. The runtime uses it to call back
into the API for its tools, and for the model.

The model is called through the organization's LLM gateway: the module connected under **Settings**, then
**Modules**, or the address in `ASK_CTRL_GATEWAY_URL`. The gateway's key for these calls is the secret
`platform/assistant-gateway-key` under **Settings**, then **Secrets**, seeded once from `ASK_CTRL_GATEWAY_KEY` on
first start, then set and rotated in Settings. A new value applies at once.

## Configuration

| Setting | Where | Default |
|---|---|---|
| The runtime | `ASK_CTRL_URL`, and `ASK_CTRL_CALLBACK_URL` for how it reaches the API | none |
| The LLM gateway | **Settings**, then **Modules**; or `ASK_CTRL_GATEWAY_URL` | the connected module |
| The gateway key | The secret `platform/assistant-gateway-key` under **Settings**, then **Secrets**; seeded from `ASK_CTRL_GATEWAY_KEY` | none |
| The model, as the gateway names it | `DISCOVERY_CHAT_MODEL` | `anthropic/claude-sonnet-5-5` |
| How much the model thinks | `ASK_CTRL_REASONING_EFFORT`: `none`, `minimal`, `low`, `medium`, `high`, `xhigh` | `medium` |
| How much of that thinking you see | `ASK_CTRL_REASONING_SUMMARY`: `none`, `auto`, `concise`, `detailed` | `auto` |
| Round trips to the model in one answer | `ASK_CTRL_MAX_TURNS` | `12` |
| Time allowed for one answer, lookups included | `DISCOVERY_CHAT_TIMEOUT` | `2m` |
| Answers one person may have running at once | `DISCOVERY_CHAT_IN_FLIGHT` | `3` |
| Questions one person may ask per window | `DISCOVERY_CHAT_RATE` per `DISCOVERY_CHAT_RATE_WINDOW` | `60` per `10m` |
| Conversation sent with a question | `DISCOVERY_CHAT_MAX_CHARS`; the oldest turns past it are left out | `64000` |

Setting any of the last four limits to `0` leaves that one unbounded.

### When it is off

Without its runtime or a gateway, the panel shows **The assistant is off.** with the reason, and the input reads
**Ctrl is unavailable**:

- "Ask Ctrl's runtime is not deployed in this organization (ASK_CTRL_URL, ASK_CTRL_CALLBACK_URL)." The runtime is
  not deployed, or the API does not know where it is.
- "Connect the LLM gateway in Settings → Modules to enable the assistant." No gateway is connected and
  `ASK_CTRL_GATEWAY_URL` is not set.

## Privacy: what is sent to the model

Every question is one or more requests to the LLM gateway, and from there to the provider behind the virtual key
the gateway uses for the assistant. Each request carries:

- A brief that describes the console and its pages, the page you are on, what is on your screen, and the ids of
  the asset, scan, connection, project, run or conversation open on it.
- Your conversation, up to the most recent 64,000 characters.
- The definitions of the tools you may use: Ask Ctrl's own lookups, the API reads both roles allow, and the
  console's commands on screen.
- The result of every lookup made for the answer. For assets: name, kind, platform, provider, account, region,
  status, up to 60 properties, and the assets they use and are used by. For scans: each source, what it found and
  why it failed. For connections: id, name, provider, account, whether enabled, and the last verification's checks.
  For findings: the check, its severity and the assets it is open on. For traces: project, run and span names,
  timing, status, errors, models, tokens and cost, and what was asked and answered, clipped to 300 characters,
  only when you hold `observability:content`. For an API read: the operation's answer, up to 48 KiB.
- For a confirmed change: how the API answered it.

Nothing is sent while the assistant is off. The conversation is kept in your browser and restored when you reopen
the panel.

<Note>
The model is told that everything a lookup returns is data from your estate, never instructions to it, and to link
only console pages. Treat its answers as a reading of the data, and check the page it links before you act.
</Note>

## The same tools from other clients

The tools Ask Ctrl reads with are also served to any MCP client, such as Claude Code, Claude Desktop or Cursor,
with a service account's key; see [MCP server](/assistant/mcp). Ask Ctrl itself is also available in editors that
speak the Agent Client Protocol, such as Zed and JetBrains IDEs, through the same `POST /v1/chat` endpoint the
console uses.
