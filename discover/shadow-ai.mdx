An asset is shadow when its kind is one the registry policy names (by default agents, MCP servers, tools, models, skills, gateways and endpoints) and it has no pending or approved registration. An Admin changes the kinds under [Policies](/govern/policies).

## The risk map

The page opens on **Map**: every account's agents and what they use, coloured by registry status. A red or amber edge is a path into something not yet governed: a registered agent that calls a shadow MCP server is as exposed as the server. **Non-compliant only** is on by default; turn it off to see the whole estate.

Select an asset to see its details and the next step: **Register it**, **Review in Approvals** or **Open in Registry**. The map needs the `graph:read` permission; without it the page shows only the list.

## Register from the list

Select **List**, then **Register** on a row, or tick several and select **Register selected**. **Register all** takes every asset that matches the filters, up to 200.

- **Owner:** when the platform names one, it is the owner and cannot be changed here; change it on the platform and the next scan reads it. Otherwise, type who is accountable.
- **Purpose:** what it does and for whom; one purpose covers every asset registered together.
- The request waits under [Approvals](/govern/approvals), and the asset leaves this list. If an Admin rejects it, it comes back.

## Who can use it

| Role | What they can do |
|---|---|
| **Viewer** | See the map and the list. |
| **Operator** | Also register assets. |
| **Admin** | Also approve the requests, under **Approvals**. |
| **Owner** | The same as Admin. |
