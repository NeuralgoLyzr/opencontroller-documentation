title: "Guardrail violations"
description: "Who tripped guardrails in the LLM gateway, what kind of rule, and how often, without the text that tripped them."
---

**Guardrail violations** shows what the LLM gateway's content rules blocked or redacted, counted per caller, so
repeat offenders stand out. It reads the gateway's own record; nothing is kept in OpenController, and the text that
tripped a rule is never kept anywhere.

Who can do this: `guardrails:violations`, held by the Admin role by default. The page names people, so it is not
part of the Viewer or Operator roles. Without it the page says **Not yours to see**.

## Who a violation names

A call names its caller only when its virtual key requires callers to sign in with an identity provider (**Callers
sign in with** on the key). Calls through other keys are counted under the key, as **No user**, with the key's name.
A notice on the page says so and links to [Virtual keys](/runtime/virtual-keys) when such calls exist.

## The summary

Pick a window: **Today**, **7 days** (the default) or **30 days**. Four numbers head the page.

| Number | Meaning |
|---|---|
| **Violations** | Blocks and redactions in the window, with a per-day trend. |
| **Callers** | Signed-in callers with at least one violation. |
| **No user** | Violations through keys that do not require sign-in. |
| **Most common** | The type that fired most, and how often. |

Below, **By caller** lists each caller, the most first.

| Column | Meaning |
|---|---|
| **Caller** | The caller's identity, or **No user** with **Key** and the key's name (or **No virtual key**). |
| **Violations** | How many in the window. |
| **Types** | Each type that fired, with its count. |
| **Per day** | A bar per day, oldest first, on one scale for every row. |
| **Last** | When the latest one happened. |

The types are **Personal data**, **Secrets**, **Prompt injection**, **Toxicity**, **Sexual content**,
**Gibberish**, **Topics**, **Keywords**, **Format** (valid SQL and OpenAPI), **Policy** (OPA, Cedar and cloud
provider checks) and **Other**.

A window holding more than 20,000 violations is counted from the newest 20,000, and a notice says so.

## Drill into a caller

Select a row to open the caller's own violations, newest first.

| Column | Meaning |
|---|---|
| **When** | When it happened; the exact time on hover. |
| **Rule** | The content rule that fired. |
| **Did** | **Blocked the prompt**, **Redacted the prompt**, **Blocked the answer** or **Redacted the answer**. |
| **Types** | The types found. |
| **Key** | The virtual key the call came through. |
| **Model** | The model called. |
| **Reason** | The rule's reason, for example a check's confidence against its threshold. |

**Show more** loads further pages, up to the newest 500.

## What a violation record holds

Each record, as the API answers it: `id`, `at`, `rule_id`, `rule_name`, `feature` (`guardrail` or `pii`, the kind
of content rule), `action` (`block` or `redact`), `stage` (`request` or `response`), `user_id` when the call named
its caller, `key_id` and `key_name`, `team_id` and `customer_id`, `provider` and `model`, `detectors` (each check
that fired and how many times, never what it matched), `reason`, and `types`, the detectors mapped to the types
above.

## Empty states

- **No LLM gateway connected**: violations are read from the gateway; connect one under **Settings**, then **LLM
  Gateway**.
- **Not recorded**: the connected gateway keeps no record of what its rules blocked.
- "Nothing tripped a guardrail in this window": the gateway answered, and there is nothing to show.

## API

- `GET /v1/guardrails/violations/users?days=7`: each caller's counts by type and by day, `days` from 1 to 30.
- `GET /v1/guardrails/violations`: the records, newest first, with `user`, `anonymous`, `key`, `since`, `until`,
  `limit` (default 100, up to 500) and `offset`.
