---
title: "Control actions"
description: "The actions OpenController can take on an agent in its own cloud, platform by platform: what each does, which credential it needs, and which combinations are not supported."
---

Control changes an agent where it runs: who can reach it, whether it runs, and whether it exists. Every attempt, successful or not, asks for a reason and is written to the audit log. The actions are offered on the **Access** card of an agent's page, under **Identity & access**.

**Who can do this:** `assets:act` (an operator's permission) to run an action. `actions:read` to read the log. Each cloud's control is a module (`control.microsoft`, `control.gcp`, `control.aws`, `control.snowflake`) that can be on or off.

## The actions

| Action | API name | What it does |
|---|---|---|
| **Share** | `grant` | Gives a person, group, role or service account access, to use the agent or, where offered, to edit it |
| **Remove** | `revoke` | Takes that access away |
| **End organization-wide sharing** | `org_wide` | Stops everyone in the organization using it; only those listed keep access |
| **Publish** | `publish` | Makes changes reach the people using the agent, where the platform has drafts and versions |
| **Block** (or **Disable** on Foundry) | `block` | Stops the agent being used, at once and reversibly |
| **Unblock** (or **Enable**) | `unblock` | Undoes the block |
| **Delete** | `delete` | Removes the agent from its cloud, for good; **Delete with cascade** also removes what only it used |

Rules that hold everywhere:

- A block applies only to an agent the registry has registered or holds as pending. The Block dialog can register a shadow agent as pending in the same step. Unblock is never refused.
- A delete must repeat the agent's name exactly and cannot be undone.
- After a change, the asset's cloud is rescanned. Until the scan lands, the card shows the change as pending. A state is never shown as Running because a read failed: it is shown as **Unknown**, with the reason.

    | Agent Builder agent (Microsoft 365 Copilot) | Not supported: only the creator shares it | No | No | Published only: blocks its catalog package. A draft cannot be blocked | Yes |

    | Microsoft 365 package shared by its creator | Not supported | No | No | Yes | No |
    | Foundry hosted agent | Yes: can use (Foundry Agent Consumer on that agent); live at once | No | No | **Disable** / **Enable** | Yes, with cascade of its Bot Services |
    | Foundry prompt or workflow agent | Yes, as hosted | No | No | Not supported: the card links to the Foundry portal | Yes |
    | Foundry agent published to Microsoft 365 (the catalog copy) | Not supported: shared by its creator | No | No | Yes: blocks the copy only; the agent still runs in Foundry | No |

    **Credentials.** Sharing, publishing and Foundry's disable run as the connection's control app. Blocking a Copilot Studio agent needs a signed-in Global, AI or Power Platform administrator (the Power Platform API); blocking anything in the Microsoft 365 catalog needs a signed-in AI or Global administrator (Microsoft Graph, `CopilotPackages.ReadWrite.All`, with Agent 365 licensing). The Block dialog offers **Sign in to Microsoft**; the sign-in lasts about an hour and is held in memory only. Deleting a Copilot Studio or Agent Builder agent also needs that Power Platform sign-in. Each dialog's **Requirements** box names what the platform needs once.

    | Platform | Share / Remove | End org-wide | Publish | Block / Unblock | Delete |
    |---|---|---|---|---|---|
    | Agent Runtime agent | Yes: a person, Google group or service account by email, or a federated `principal://` identity, on the agent's own IAM policy; can use or can edit | Yes: **End organization-wide access** removes whole Workspace domains | Not applicable: a deployed change is served | Not supported: Google Cloud has no switch that stops one agent.     | CX Agent Studio app | Not supported: people reach it through its channels | Yes: **Turn off public web access** | Yes: the draft becomes a new version | Not supported: remove its deployments in the Google Cloud console | No |
    | Managed Agent | Not supported: it belongs to the person who made it | No | No | No | No |

    **Credentials.** Everything runs as the connection's app; there is no directory search, so you type the email. Google Cloud applies a change within a few minutes.
  </Tab>
  <Tab title="AWS">
    | Platform | Share / Remove | End sharing with everyone | Publish | Block / Unblock | Delete |
    |---|---|---|---|---|---|
    | AgentCore runtime | Yes: an IAM role or user ARN, or an account id, in the resource policy; can use only | Yes | Not supported yet | Yes: a Deny of every call is added to the resource policy; Unblock removes only that Deny | No |
    | AgentCore gateway | Yes, as runtime | Yes | Not applicable: a gateway has no versions | Yes, as runtime | No |
    | AgentCore harness | Not supported: no resource policy | No | No | No | No |
    | Credential providers, workload identities, Agent Registry records | Not supported | No | No | No | No |

    An agent with a JWT authorizer cannot be shared or unshared from here (its allow-list is the authorizer's), but it can be blocked. Revoking the agent's own account is refused: block it instead.

    **Credentials.** The connection's control role, created from `aws-control-role.yaml`, must be allowed to change the resource policy. CloudTrail records the change with the operator's name. AWS applies it at once.
  </Tab>
  <Tab title="Snowflake">
    | Platform | Share / Remove | End access for everyone | Publish | Block / Unblock | Delete |
    |---|---|---|---|---|---|
    | Cortex Agent | Yes: a role or a user from the account's directory; can use (USAGE) or can edit (MODIFY) | Yes: the PUBLIC role loses its grants | Yes: adds the agent to CoWork | Yes: takes the agent from its owner role and revokes every grant; the grants are kept in `OPENCONTROLLER.STATE.BLOCK_SNAPSHOTS` and given back on Unblock | No |
    | Snowflake-managed MCP server | Yes: can use | Yes | Not supported | Not supported: block the agents that call it | No |
    | Cortex Search service | Not supported: reached through the agents and MCP servers that use it | No | No | No | No |

    A grant inherited from the schema, database or account cannot be revoked on one object; the log says which stayed.

    **Credentials.** The connection's control role holds MANAGE GRANTS on the account and USAGE on the connection's warehouse, and may write `OPENCONTROLLER.STATE.BLOCK_SNAPSHOTS`. The setup script grants all of it. Snowflake applies a change at once.
  </Tab>
</Tabs>

Anything not in these tables, including every Databricks and Anthropic asset, has no control actions: the Access card is not shown and the asset is read-only.

## What the Access card shows

| Row | Meaning |
|---|---|
| **State** | **Running**, **Blocked** (Microsoft's and AWS's word), **Disabled** (Foundry's), **Deleted**, **Removed** or **Unknown**, with its source: live, or "as of the last scan" |
| **Reach** | Who can use the agent: **Anyone, outside the organization too**, **Everyone in the organization**, a count of people and groups, or a line saying the inventory has not read it |
| **Owner**, **Editors**, **Users** | The people and groups listed, each with **Remove** where removal is supported |
| **Delete** | Shown only where the platform supports it |

A Copilot Studio agent can be blocked in Microsoft 365 as well; the card says **Blocked in Microsoft 365** and links to the admin center, since only it lifts that block.

## API

| Method | Path | Returns |
|---|---|---|
| `GET` | `/v1/assets/{asset_id}/actions/available` | Which actions apply now, and why not |
| `POST` | `/v1/assets/{asset_id}/actions` | Run an action; `publish` query defaults to true |
| `GET` | `/v1/assets/{asset_id}/principals?q=` | People and groups to share with, where the cloud has a directory |
| `GET` | `/v1/assets/{asset_id}/actions/delete/dependents` | What a delete with cascade can remove too |
| `GET` | `/v1/actions` | The audit log of actions |
